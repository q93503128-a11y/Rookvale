# UI / UX

**Status:** Open

## Goals

- Important information should be understood quickly.
- Exploration should not be buried under permanent UI clutter.
- Combat must expose enough information for tactical party play without becoming spreadsheet-like.
- Desktop, touch, and Roblox control layouts should share the same information architecture even when controls differ.
- UI should look deliberately designed, not like default web controls or default Roblox GUI.

## Required future flows

- first launch / character start;
- overworld HUD;
- NPC interaction;
- party management;
- combat command selection;
- target selection;
- inventory / equipment;
- class and progression screens;
- quests / activities;
- map / travel;
- settings and accessibility.

## Validation approach

During web development, important screens should be checked visually at multiple aspect ratios and input assumptions. Layout errors, weak information hierarchy, excessive clicks, unclear states, and poor readability should be treated as design bugs rather than cosmetic polish tasks.

## Open questions

Actual layout language, iconography, menu depth, HUD density, and combat presentation will be designed after the combat and world interaction models are clearer.
