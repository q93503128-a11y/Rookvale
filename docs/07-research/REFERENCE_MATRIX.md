# Reference Matrix

**Status:** Active

This document will track what Rookvale studies from external games and, equally importantly, what it does **not** copy from them.

| Design area | Reference candidates | What to study | Rookvale decision |
| --- | --- | --- | --- |
| Overworld -> turn-based encounter structure | Hero of Aethric | Exploration rhythm, encounter transition, world-content density | Broad structural reference only |
| Multiplayer exploration | TBD, including relevant Roblox RPGs | Party formation, seeing other players, drop-in/out friction | Open |
| Party turn-based combat | TBD | Simultaneous choice, initiative, party role interaction | Open |
| Class advancement | TBD | Branch clarity, respec rules, role identity | Open |
| Boss encounters | TBD | Telegraphing, phase structure, support-role value | Open |
| Pixel world presentation | TBD | Readability, scale, environment density | Open |
| Inventory / equipment UX | TBD | Information hierarchy, comparison speed | Open |
| Mobile UI | TBD | Touch targets, HUD density, menu depth | Open |
| Roblox UI | TBD | Cross-device readability and platform expectations | Open |
| Social / party UX | TBD | Invite flow, grouping, reconnect behavior | Open |

## Research rule

References should be collected per system. A strong implementation may inspire a principle or mechanic, but the final design should fit Rookvale's own world, combat, multiplayer, and cross-platform constraints.
